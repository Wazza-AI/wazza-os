    What's new

    What changed in Wazza OS since version 0.2.0 (build b8069fa40737). Wazza OS: the Apps page now works like an iPad, big apps such as Blender download from their official sites the first time you ask for them so Wazza OS is much lighter, every VM gets Ubuntu's newest kernel and security updates safely, and the agents, the tabs, the VMs and Wazza OS's own updates get many fixes.

    In short#

    • Hermes, the agent inside every VM, is now version 0.23.1, and it can also run on this computer for a Local Chat, on your own Custom API.

    • When a model provider refuses a turn (a wrong key, too many requests, a blocked message, a proxy refusing the connection), the Chat says what happened and what to do next, never "Internal error".

    • Keys stay private: Wazza OS never shows a key back to you or to a model, whole or in part, even when a provider repeats it in an error, and no AI provider is asked anything before you give it a key or sign in.

    • The model window offers Apply to: This chat, All chats, or Default for new chats, names every model in plain words, and says a Custom API model is saved in Sign In › Custom API.

    • "Keep going until done", a new switch in each Chat's settings, makes your message the Chat's goal: its agent keeps working until it is done, on every agent.

    • Your conversation stays with the Chat when you switch agents, reopen it from History or restart Wazza OS, now also for Hermes in a VM.

    • Codex runs a new, lighter build that starts faster and uses less memory; Claude Code and Prime Agent are on newer versions.

    • The skills you save in Settings now reach every Chat, whichever agent it runs.

    • Chats read better: tool rows show each tool's own result, inline code and file previews are drawn cleanly, models are named in plain words, and a new Chat says it is starting.

    • Regenerate and an edited message start from the conversation before the answer they replace, and a message waiting for its agent is sent once, never twice.

    • Settings: you can remove a skill you added, sections with their own Save button say "Saved", and Sign In's Website switch works again.

    • Copy and paste with VMs: only your own paste copies files from this computer into a VM; an app that asks for them without a paste gets nothing, and when Wazza OS cannot tell, it asks you first.

    • The Apps page now works like an iPad: pages of apps you swipe through, apps you press and hold to move, and you choose how many apps fit on a page.

    • Big apps such as Blender are no longer inside the download; each one downloads from its official site the first time you ask for it, so Wazza OS itself is much lighter.

    • Every app now updates through Wazza OS's own update. An app you have open keeps working while its update waits, and a failed update never breaks the version you had.

    • Every VM gets Ubuntu's newest kernel and its security updates, safely. A new kernel is kept only if the VM still starts and still uses your graphics card. Otherwise it goes back by itself.

    • New app: Notion. Many apps were updated to newer versions.

    • The browser is called Chrome when your VM runs Google Chrome, everywhere you read its name.

    • Installs say what really happened in plain words, and an app can now be repaired in place from its menu.

    • One tab strip for all your VMs, with each VM's CPU and RAM stacked in the Applications sidebar when several run.

    • Wazza OS asks before your work is lost (Save, Close without saving, Keep open, with Save through the tab's Chat and "Remember my choice"). It asks before closing a tab, Quit, a VM's Stop or a VM's Restart, in every window, and also for the apps you started or installed yourself in a VM.

    • When an app asks about its own unsaved work, its own dialog is the one question you see, and the tab stays.

    • Tabs and their projects come back after a restart; History reopens the file you saved.

    • Typing into a busy VM no longer drops or reorders keys. Files copied on your computer paste into VM apps.

    • Wazza OS reacts to changes instead of checking over and over, so it uses less of your computer at rest.

    • Some updates now install without restarting Wazza OS, wait for your apps instead of breaking them, and put the previous version back if anything fails.

    • Updates explain themselves: what blocks an install, what Check now found, and which apps did not come back after a restart.

    • Updates follow your proxy and install on openSUSE Tumbleweed with SELinux.

    • Agents can save their own commands, several tool calls in one, and use them in every Chat, also from Hermes in a VM.

    • A new Deep dark theme: pure black and neutral greys, in Wazza OS and in its Chat.

    • Hundreds of smaller fixes across the tabs, the VMs, the picture of each VM, the agents and their tools, each listed below in its area.

    • The tests, the guide, the build tools and Wazza OS's inner workings changed a great deal too: every such change has its own line in the sections at the end.

    Hermes (the agent in each VM, and on this computer)#

    • Hermes is now version 0.23.1; the GitHub Copilot sign-in it ships finds your login every time.

    • A Local Chat can run Hermes on this computer, on your Custom APIs; its own connection to Wazza OS never goes through your proxy.

    • A Local Chat with nothing to run on says so plainly, with a working API keys button; it also says that a Wazza sign-in alone does not run Hermes on this computer.

    • When a Chat asks Hermes on this computer for a model your sign-in's plan does not offer, it says so before it starts, naming the model you asked for.

    • A Hermes Chat in a VM reopens its own conversation after Wazza OS or the VM restarts, or says it could not instead of quietly starting a new one; a Chat that keeps its own conversation never takes over a half-started one meant for another Chat.

    • When Hermes's model provider fails, the turn ends once, in Wazza OS's words: the same message no longer appears twice, and a failed run is never taken for an answer.

    • A new Hermes Chat with nothing to run on says so in its own words instead of offering a model list that would never come; Settings, the model window and the default check offer a new Hermes Chat the same models.

    • Hermes in a VM never asks its own data-sharing question: Wazza OS answers it the way you chose.

    • Each of Hermes's goal notices is a paragraph of its own, never run together with the answer.

    • Hermes's skills arrive at most once per Chat, so its later messages never wait for them.

    • After you add your first global MCP server, a VM Chat's Hermes restarts before its next message so it can use it, and a Hermes still running background helpers is never restarted, so their results are not lost.

    • Installing a global MCP server, and a long call of one of its tools, no longer end with "exit 1: no answer" while the server's work is still going on.

    • The kept-elsewhere wait lives in the one bind, so no bind path can skip it.

    • A VM Hermes Chat's restart for a global server's first add is decided by what its process holds, as its launcher says it at the session's start.

    • The local door's timed-out call is a Local Chat's Hermes's.

    • Seat "tui" is not a shell; the tab's Hermes screen is seat "hermes".

    • Only a WHOLE list says "not offered"; the set mirrors the picker exactly; every parse before any write.

    • The default for new Chats is chosen only from the agent's offered list, the picker's own, and takes its route from it.

    • The VM addon's comment names the true place too.

    • The new Chats' hint names Settings' own place, from one source.

    • A refused turn is said as the provider's refusal, per status, to the person.

    • Ui.do's visible Hermes check takes the tab Chat's pick its trigger carries.

    • The time-limit words name their real place in Settings.

    • A person-facing 'Run a visible Hermes check' in the bound tab's Desktop menu, on the tab Chat's model.

    • A visible Hermes check runs on the model chosen in its tab's Chat.

    • A visible Hermes run that fails after it starts closes its own terminal and its run folder.

    • The visible Hermes turn runs on the person's own provider plan, chosen before anything is opened, and Wazza OS judges its receipt against that plan.

    • A message whose tab is already closed is dropped once, said, never deferred for a session that cannot come.

    • A background VM's tab close runs over that VM's own serial.

    • The sign-in catalog snapshots the registry the payload's Hermes holds, shipped plugins included.

    • A Local Hermes sandbox's own network forwards Wazza OS's local door while it is bound, keyed on the start's own door key, so a Chat's turns reach the door after a Wazza sign-in.

    • When Wazza OS cancels a turn for its budget, it ends only that Chat's turn: no background work is stopped and no dead prompt waits ahead of your next message.

    • After a budget cancel the Chat's goal stays active, and a failure without an HTTP status names its kind.

    • The Hermes adapter of Wazza OS's ONE per-turn upstream budget: the launcher tells each failed model call, Wazza OS decides and cancels.

    • A Local Chat's Hermes starts without the extra scans.

    • A Local Chat's Hermes starts by Wazza OS's launcher.

    • A Hermes Chat in a VM gets that VM's global MCP servers as one more server, only while the VM's list has one.

    • Native's none says words true however it was reached, never "nothing is signed in yet".

    • The real transition takes back Wazza OS's OpenRouter declarations.

    • The Hermes sign-out of the last Anthropic account no longer raises ImportError.

    • A Chat turn whose skills preload raises is never reported 'current'.

    • A VM Hermes Chat makes, lists and runs the user's saved commands like a host Chat.

    • Each Hermes run keeps its own view of the skills that come with Wazza OS.

    • A per-turn snapshot of Wazza OS's shipped skills from the VM store.
