    How an agent uses them#

    Wazza OS runs apps in virtual machines (VMs vm-1 to vm-8) on this computer; each app opens in a tab, and each tab has its own Chat (an AI agent). These tools are Wazza OS's own command line (wazza --gui ...): each one runs that CLI and answers its output and exit status (exit 2: the CLI refused the arguments, its usage text says how; nothing was done).

    The typical flow#

    1. status: is the Wazza OS app running? If not: start it with start (unless the user said not to start it); it waits until the app answers and returns its window state (check says what this computer lacks when it cannot start).

    2. vm {verb: "list"}: the VMs. vm-1 starts by itself with Wazza OS (its boot takes a minute or more): never start it again. vm {verb: "start", vm: "vm-2"} is for vm-2 to vm-8: it starts a stopped one (minutes; list again). VM backups (only when the user asks): vm {verb: "backup", vm} saves a zip in Downloads; vm {verb: "restore", backup: <its id from verb backups, or its zip's path>, start: true} makes a new VM from it and starts it (verb backups follows the restore); into: "vm-1" with yes: true replaces vm-1 (it stops vm-1, its disk goes for good, it starts again); start {vm1_backup} starts the app with vm-1 made from a backup.

    3. ui {verb: "do", action: "open_app", args: {appId: "files", vmId: "vm-1"}}: the app opens in a background tab (the user's screen stays as it is); ui {verb: "do", action: "vm_tabs_read", args: {vm: "vm-1"}} names its tab id. app {verb: "list"} lists the apps, app {verb: "status", app_id} whether one is installed.

    4. Chat: ui {verb: "do", action: "chat_send", args: {vmId, tabId, childId: "", text}} (childId "": the tab's own Chat, always named; a tab's Chat that never started starts behind the view); then chat_transcript {tab, vm, last: 5} reads its answer.

    5. Drive (GUI work in a tab's app): drive {verb: "look", vm, tab} returns an image and a snapshot_id; drive {verb: "act", vm, tab, args: {snapshot_id, action: "left_click", x, y}} runs one action and returns the next view: check it, then the next act.

    6. Files: explorer (a VM's files; this computer's with computer: true; copy_to_vm, upload). Settings: vm_memory, vm_disk, vm_gpu, gpu, chat_model, timeouts, local_services, clipboard. Updates: ui {verb: "do", action: "update_read"} and "update_check" (installing an update is the user's own). Everything else: invoke.

    7. Sign the app's Chats in (the user's own accounts; a token is never copied from one program to another): provider_signin {verb: "status"} lists the providers, their methods and what is signed in. A login: provider_signin {verb: "start", provider, method: "oauth"} answers its attempt and auth ids; {verb: "open", attempt, auth, browser: "external"} opens its page in the user's own browser, where the user approves once; {verb: "poll", attempt, auth} until it is done; {verb: "commit", attempt, auth} keeps it; status then shows it verified (it is signed in only once verified). On a server (no browser here): open answers the link instead; give it to the user, who approves on any device and gives you the code it shows; {verb: "submit", attempt, auth, prompt, secret: <the code>} (sent on stdin). Claude's plan login (Claude Code's own, as setup run's logins): invoke {verb: "modules_call", module: "agent", method: "claude_code_signin", args: {op: "start"}} answers its attemptId; {op: "status", attemptId} names its authUrl: the user opens it, signs in and is shown a code; {op: "submit", attemptId, code}; {op: "status", attemptId} until state done, its account named. An API key: provider_keys {verb: "add_from_env", provider, from_env: <variable>} reads it from your own environment (the user exports it, e.g. OPENROUTER_API_KEY): it never passes through your model; add_from_file reads a 0600 file.

    8. Screens: screenshot answers the Wazza OS window's own picture (its virtual screen, or on a desktop the app's own window); native_input begin, then focus/pointer/click/key/text/scroll, then end, acts in that window only. Look before you click: screenshot, one action, screenshot again.

    The rules#

    these tools act with the user's own CLI rights: keep the user's screen as it is unless the user asked to see something (no focus, no Settings page opened on its own). A refusal names its code and why (user_only_app: Computer Control opens only by the user's own click); busy or not ready: call again in a few seconds; ui_outcome_pending (a window action still running after the CLI followed it, about 45 s): read it with ui {verb: "outcome", outcome: <its id>}, never send the action again. Destructive verbs (delete, reset, remove_all, quit...) only when the user asked for exactly that. pro and wazza_tools runs spend Wazza Pro credits.

    Claude Code shows these instructions to its model; Hermes and Prime Agent never do (they show only each tool's name and description), so each tool's description below carries the same rules.

    start#

    Start the Wazza OS app when it is not running (CLI wazza start): on a desktop as the user's own start (its window on the user's screen), with no display (a server, SSH) on its own virtual screen, the manual's server mode. Already running: it says so and starts nothing. It waits until the app answers (timeout, default 120 s) and answers its window state as status does. Call it when status says the app is not running, unless the user said not to start it. vm-1 then starts by itself (its boot takes a minute or more): never start vm-1 again. Only when the user asked for it: vm1_backup (a VM backup's zip on this computer, or its id from vm {verb: "backups"}) makes vm-1 from that backup as the app starts, its setup skipped (vm {verb: "backups"} follows the restore): {"vm1_backup": "/srv/backups/wazza-vm-1.zip"} runs wazza start --vm1-backup /srv/backups/wazza-vm-1.zip. A vm-1 that already has a disk is refused unless replace_vm1 and yes are true: its disk and everything in it are then replaced for good. The app already running never takes it (it says so): vm {verb: "restore", into: "vm-1", yes: true} replaces vm-1 there.
