    Glossary

    The words of Wazza OS, in plain language, each with the page that explains it.

    Agent
    An AI that works for you in a Chat: it reads your message, uses tools (commands, apps, files) and answers. See Chats.
    API key
    A secret code from an AI provider (OpenRouter, OpenAI, Anthropic…) that lets Wazza OS use its models, billed to your account there. See API keys.
    App
    A Linux desktop program of the VM (GIMP, Blender, Chromium…), or a web app in the VM's browser. Each opens in a tab. See Apps.
    App journal
    Wazza OS's notes of the menus, clicks and keys you use in the VM's apps (never a password), from which agents learn how-to lessons. See App journal.
    App skill
    The skill files of one app: what the agent of that app's tabs knows about it. See Edit an app's skill.
    App tools
    An app's own tools for agents, from its MCP server: GIMP has 40. The Chat of a tab where the app is open gets them. See Give your app tools.
    Chat
    The conversation beside a tab's app, with its agent. Every tab has one. See Chats.
    Company folder
    A folder of your company's file server (SFTP, FTPS or SMB) that every VM sees, read-only, at ~/Company/<Name>. See Company folders.
    Compact
    Summing up a long Chat so it fits the model again; the Chat goes on from the summary. See Compact a long Chat.
    Computer Control
    A special Chat whose agent may see and use your own computer's screen, keyboard and mouse, after your click on Start, until its tab closes. See Computer Control.
    Custom API
    An AI endpoint you add by its address (your own server, a company gateway, a local model). See Custom API.
    Drive
    How an agent looks at an app's screen and acts on it with the mouse and keyboard, in any app. See Drive.
    Explorer
    The file browser of the VM's files, at the far left of the tab strip. See The Explorer.
    Harness
    The agent program that runs a Chat: Hermes, Prime Agent, Claude Code, Codex or Antigravity. Each works with the models its logins and keys reach. See The agents.
    Helper agent
    An agent a Chat starts for part of a job: visible in its own app tab, or hidden in the background. See Several agents at once.
    Home
    The menu at the left of the window: Apps, Settings, Sign in, History, Update, Notifications, Feedback, and the VM card. See Home.
    KVM
    Linux's hardware virtualization, which runs the VM at full speed. Your computer must have it turned on. See What your computer needs.
    Lesson
    A short piece of know-how Wazza OS learned from a Chat and added beside a skill, with its evidence. See How Wazza OS learns.
    Login (plan login)
    Signing in with an AI plan you already pay for (Claude, ChatGPT, Grok, Google…), instead of a key. See Logins.
    MCP
    The Model Context Protocol: the standard way agents get tools. Wazza OS gives every Chat its tools through its MCP server. See The Wazza OS MCP.
    Model
    The AI behind an agent (for example MiMo, Claude Sonnet, GPT), from a provider. Each Chat has its own. See Choose the agent and the model.
    Native GPU
    Lending one of your graphics cards to the running VM, for full-speed compute. Experimental. See Lend a card.
    Persona
    An agent role (3D artist, film director, writer…): how it works and the skills it loads; it learns from its Chats. See Personas.
    Provider
    A company that runs AI models (OpenRouter, OpenAI, Anthropic, Google, xAI, DeepSeek…).
    Recipe
    How an app installs in the VM and starts, with its optional tools and skill. See Add your own apps.
    Seat
    Where Drive acts: an app tab of the VM, the agent's terminal, or (Computer Control only) your computer.
    Setup file
    A JSON file that does the first start's steps from the command line. See Set up without clicks.
    Skill
    Written know-how an agent loads before it works: procedures, checks, pitfalls. See Skills, learning and personas.
    Sync
    Keeping your skills, files and Chat history with your Wazza OS account, for your other computers. See Sync & team.
    Tab
    One app of the VM with its Chat, in the strip at the top of the window. See Tabs.
    Tool
    One operation an agent can call (open an app, export an image, click). In Apps, a tool is also a package with no window that gives the VM a capability (Git, GPU for apps, Search).
    Virtual screen
    An invisible screen Wazza OS brings when the computer has none, on a server. See The virtual screen.
    Virtualized GPU
    The default way the VM's apps use your graphics card: shared with your computer. See Desktop apps and the GPU.
    VM (virtual machine)
    The computer of its own that Wazza OS runs on yours: Ubuntu, with its desktop, apps and files. Apps and agents work there. vm-1 is the main one; you can add vm-2 to vm-8. See Virtual machines.
    VM card
    The card at the bottom of Home with the VM's state, CPU, memory and graphics. See The VM card.
    Wazza OS account
    Your account with Wazza OS (email and password, or online): sync, teams, and Wazza OS models. Optional: Chats work without it. See Your Wazza OS account.
    Web app
    A website that works like an app (Gmail, Google Docs, Word, Teams), opened in the VM's browser as its own tab. See Web apps.
